Backend Deployment Plan

How the proposal becomes a save-capable website for a webmaster

What Is Ready

A real editing backend is included

The public proposal can run as a static preview, and it can also expose a token-protected serverless API that commits content edits back to GitHub when production secrets are configured.

The repository also includes a Node.js backend for hosts with persistent disk. In either mode, the editor at /admin/editor.html detects the backend, reports its health and persistence mode, loads the editable JSON from it, enables Save buttons, and persists changes through the same API paths.

Launch Checklist

Backend hosting steps

1. Choose Backend

Use GitHub-backed saves on Sites, or deploy the Node backend to Render, Railway, Fly.io, or a VPS.

2. Set Admin Secret

Configure GRSB_ADMIN_TOKEN as a long random value. The editor requires this token before saving.

3. Configure Storage

For Sites, set GRSB_GITHUB_* variables. For Node, set GRSB_CONTENT_DIR to persistent storage.

4. Start or Redeploy

Redeploy Sites after environment changes, or run npm start on the Node host.

5. Verify Health

Open /api/health. It should report ok: true, the persistence mode, and adminApiEnabled: true.

6. Test Editor

Open /admin/editor.html, enter the token, make a small content edit, and save.

7. Point Domain

After approval, point the official domain to the approved production host.

Quality Gate

Repeatable smoke tests

The repository includes npm test, which builds the static proposal, verifies key public routes, confirms the static preview does not expose the write API, starts the Node backend, checks /api/health, verifies authorized saves, and confirms unauthorized writes are rejected.

After production secrets or Node hosting are configured, npm run test:production-backend performs a reversible live edit through the public API and restores the original content. A GitHub Actions workflow is also included so local smoke checks run automatically once the project is placed in a GitHub repository.
